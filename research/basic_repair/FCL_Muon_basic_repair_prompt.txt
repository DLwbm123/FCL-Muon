A. 立即完成零训练的固定logit干预
随包fcl_basic_repair_tools.py已用NumPy合成验证。它不加载模型、不访问网络，
labels只用于指标计算，绝不用于选择变换。

规则只有一个：
对每个固定训练任务的10类块，逐样本减去该块的logit均值，然后在全部30类argmax。
z'_c=z_c-mean_{j in block(c)}z_j。
每个任务块内部argmax必须不变。
使用的是类别所属训练块，不是测试样本的真实taskID。
不要试多个temperature/offset/normalization再选test最好者。

示例：
python fcl_basic_repair_tools.py --self-test

B. 一次T1闭环，固定编码器比较全局分类头
1. 枚举实际checkpoint。
   如果T1模型未保存，跑原MuLoRA-FL的第1任务：
   原manifest、IN21K权重、Q/V-r32、RRS、5round×5epoch、batch16、原lr/schedule。
   保留轮末和T1模型，避免再次只剩最终T3 latest。
   加诊断不能改变训练随机流；保存/恢复RNG，最好用独立进程评估。
   先不引入history、LoRM全48模块、训练A或别的研究组件。

2. 当前训练图像在客户端，向所有客户端广播同一个已聚合的global encoder。
   使用deterministic transform提取归一化CLS特征z=f(x)/||f(x)||。
   全局prototype/Gram必须来自这个同一个encoder，
   不能把各客户端不同local encoder下的特征当同一坐标系相加。
   merged base和adapter不能重复使用；先验证merge前后输出等价。
   特征只在当前任务期间客户端临时保存，不形成旧任务样本回放库。

3. 在同一T1最终encoder上比较四个readout：
   H0 原pipeline的cosine head；
   H1 全局cosine prototype；
   H2 同结构、scale16的全局拟合cosine head；
   H3 联邦闭式ridge线性probe。
   这是便宜的头部计算，不再分别训练四个ViT。

H1：
s_kc=sum_{x:y=c}z(x)，n_kc=该类样本数；
server s_c=sum_k s_kc；head row=s_c/||s_c||。
只需class sums/counts，不上传图像。
不存在类/近零sum必须报错或执行预声明规则，不任意补向量。
不能先平均每客户端prototype再不按类样本数加权。
随包global_prototype_rows提供raw-stat计算参考。

H2：
固定encoder和所有features，只有一个全局cosine head及其optimizer state。
每个head更新步汇总各客户端样本加权梯度，server更新一次；
不用多个local head走多步之后再FedAvg。
full-batch梯度求和对应同一个pooled current-task objective。
这项与H0函数类相同，比只换ridge更能区分head优化/聚合问题。
head拟合预算、初始化、lr/停止规则在查看test结果前固定并记录；
额外头部计算单列，不能冒称原faithful训练预算。

H3：
augment z with intercept: ztilde=[z;1]；
C_k=sum ztilde ztilde^T，R_k=sum ztilde onehot(y)^T；
W=solve(C/N + lambda*diag(I,0), R/N)。
用solve、不显式inverse；raw sums不得再乘n_k。
W是线性head，不要normalize W后仍称ridge最优解。
同一统计合并应与pooled ridge在FP64数值误差内相同；随包已有合成验证。

4. 对原始frozen pretrained encoder也计算H1和H3。
   共用同样样本、transform、feature normalization、head拟合规则。
   这用于判断适配损坏特征，不能拿IN21K预训练head的类别输出作CIFAR预测。

验证与test规则
- 若完整复用已训练T1模型，其训练图像只能作为head fitting数据；
  不能从这些已经参与encoder训练的图像中事后划出一部分，
  再声称它们是encoder从未见过的独立validation。
- 对已有full-train模型，H1是无超参的预声明干预；H2/H3参数预先锁定，
  test只用于一次性诊断，不据test选择最佳head/lambda/lr或停止点。
- 若需要选择修复方案/参数，使用从新T1训练开始就隔离的train-derived validation；
  它不得进入encoder训练、RRS统计、prototype拟合或head fitting。
  所有候选共用该划分；标清与原full-train run不同的data identity。
- 最终full-train确认运行只用已锁定配置，不能继续看test调参。
- 原83.3与新训练子集上的数值不能装成严格同协议复现；
