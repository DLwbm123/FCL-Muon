# Implementation notes

- `fcl.math` contains explicit RRS, compact-SVD diagnostic polar, separate MuLoRA Eq.3 SSB and Takezawa dimension-scaled NS, client updates and shared-A weighted aggregation validation. Zero/rank-deficient polar never fills null modes. Finite NS is not required to equal polar exactly.
- `fcl.model` adds Q/V factors around fused QKV and merges only once per task. K is untouched by the adapter. Module names and shapes are logged. Backbone remains frozen, while B and only current cosine rows train.
- `fcl.data` uses pinned upstream split on indices, preserving YAML mapping and sample identities. Full partition manifests contain split, per-task/client indices, labels and class order; same seed/alpha/client configuration is shared between methods. Kornia transformations preserve upstream BASE_TRANSFORM followed by batched augmentation.
- `fcl.train` serially simulates clients on one GPU. Each method computes its own full current training statistics under its own entering-task backbone; there is no cross-method statistics cache. History is committed once after merge. Checkpoints are atomic communication-boundary snapshots. In-memory client states are keyed by actual integer client ID.
- Checkpoints retain model/A/B/heads, raw history, pending statistics, committed task IDs, task/round scheduler position, raw m, local/global c, config, manifest and weight hash, Python/NumPy/torch/CUDA RNG. `num_workers=0` and default sampler use the recorded main process RNG. A signal during a round allows completion if grace permits, otherwise the last complete round is recoverable. Original run clock is retained on resume.
- Forgetting at final stage T is the mean over old tasks i<T of max_{j=i..T} A[j,i] − A[T,i]. Final task is excluded. Accuracies are fractions, micro uses sample counts; task macro and mean stage micro are separate.
- Smoke has a dedicated config: 2 clients, first 2 official tasks, 2 rounds, 1 epoch, at most 2 actual batches for statistics/train/test. It does not represent full-epoch scientific evidence. Pilot/formal have no sample truncation. Main protocol E=5 epochs and drop_last=False.
- Event logs distinguish first actual single-step delta B, cumulative local B, aggregated B. Detailed spectra cover the first actual step in each local round and each local/aggregated cumulative B, for all 24 matrices. This sampled single-step diagnostic must not be generalized to all optimizer steps. Tensor payload bytes are logical simulated communication; Python/message framing and physical network traffic are not measured in serial simulation.
- No server auxiliary images, replay, task labels for inference or test-dependent hyperparameter/checkpoint selection.

The latest user correction supersedes the original prompt shared-operator clause. MuLoRA-FL uses no dimension multiplier in its Eq.3 step. FedMuon combination uses Takezawa scaling; controlled-operator comparison is deferred as a separately named ablation.

LoRM comparison uses the pinned upstream methods directly, with official rank16/AdamW/constant LR/A-B alternation/linear head/RegMean and AMP16 defaults. Its separate manifest-driven harness records actual optimizer steps and evaluates the post-temporal-merge model over all seen labels. Round checkpoints include server base/head, current factors, old temporal mean, accumulated weighted Grams, accumulated Grams, materialized evaluation weights, client task/round/alternation counters, RNG and AMP scaler. Client factors/head are re-broadcast from server each round; old per-client Gram tensors are disposable and recollected on the current task as required by upstream. No old raw examples are re-read. Freeze checks guard the non-optimized LoRA factor during client training. The LoRM job has its own persisted clock and process-group deadline, monitored by the same existing project heartbeat.
