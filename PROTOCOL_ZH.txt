# 六、MuLoRA-FL 的精确定义

每个任务、每个适配层执行以下流程。

## 6.1 任务开始：构造共享 A

使用本方法自己的任务前全局模型 W_(t-1)，在 B=0 时收集当前任务输入特征。

客户端累计未中心化、未归一化二阶矩：

`S_(k,t) = Σ x x^T`

服务器直接求和：

`S_t = Σ_k S_(k,t)`

原始二阶矩已经包含样本/token 数量，不能再乘一次样本数权重。

维护进入任务前的历史统计 `H_raw`：

1. `H = H_raw + epsilon * I`
2. Cholesky：`H = L L^T`
3. `S_white = L^(-1) S_t L^(-T)`
4. 提取领先 r 维特征子空间 U
5. `Z = L^(-T) U`
6. Thin QR：`Z = Q R`
7. `A_t = Q^T`

要求：

- 使用三角求解，不显式求逆；
- 不能省略映射回原空间后的 QR；
- 不能把 RRS 换成 PCA 或随机正交基后仍沿用名称；
- 首版使用精确特征分解作为 reference，随机化版本以后再做；
- 分解使用 FP64，数值稳定项及实际 jitter 显式记录；
- epsilon 原文数值不明确时，依据训练统计尺度作出稳定、可复现的选择，写入配置与审计表；
- 默认统计 patch tokens，不包含 CLS token，记录该补全约定；
- 正式统计使用当前训练样本的一次完整前向；smoke 的采样缩减必须单独标记；
- 只有输入张量完全相同的 Q/V 才可共享统计。

同一次运行、同一任务的所有客户端共享数值相同的 A。

不同方法从后续任务开始可能有不同的 W，因此不能直接共用另一方法的 S、H 或 A 缓存。缓存键必须包含 checkpoint hash、task、layer、split、预处理和 token 策略。

## 6.2 本地训练和聚合

任务开始时：

- 冻结 W_(t-1)；
- 固定 A_t；
- B_t 初始化为零；
- 初始化本任务对应的客户端 optimizer states。

每轮：

- 客户端从服务器当前 B 开始；
- 本地训练完整 5 epochs；
- A 不变化；
- 服务器按 `p_k = N_k / Σ_j N_j` 聚合 B；
- N_k 是当前任务实际训练样本数，不是 step 数或重复访问次数。

共享 A 时，应验证：

`(Σ_k p_k B_k) A = Σ_k p_k (B_k A)`

每轮不能把 B 重新清零。

## 6.3 任务结束

仅执行一次：

`W_t = W_(t-1) + B_t A_t`

然后：

- 将本任务开始时收集的 S_t 加入 H_raw，一次且仅一次；
- 进入新任务后重新构造 A、清零 B；
- 重置与旧 B 坐标绑定的 Muon/FedMuon states；
- 不重新读取旧训练样本刷新历史特征。

明确说明历史统计是过去表示下的代理，不声称它等于当前模型下重新计算的所有旧特征。

# 七、Muon 与 FedMuon 的共同算子和状态

## 7.1 共同的 Muon operator

两方法共享同一个显式实现，隔离 FedMuon correction 的影响。

第一版使用 Takezawa 官方 FedMuon 实验代码中的算子：

- 原始动量：`m <- beta*m + (1-beta)*g`
- 项目默认 beta=0.9；
- 无 Nesterov；
- NS 输入按 Frobenius norm + 1e-7 归一化；
- 系数 `(3.4445, -4.7750, 2.0315)`；
- 5 次 NS；
- NS 和动量使用 FP32；
- 按矩阵形状选择较小的 Gram；
- 最终乘 `sqrt(max(d_out, r))`。

将维度缩放与基础学习率分别记录。这个 operator 是统一项目配置，不能声称未知的 MuLoRA 原实现参数已经被逐项复现。

初始 B 学习率先采用：

- CIFAR-100：2e-4；
- ImageNet-R：1e-4。

采用任务内连续 cosine schedule，不在每个通信轮重启。记录每个客户端的真实 step 数和 LR。B 默认 weight decay=0。

如果后续调参，使用训练集分出的验证数据、相同搜索预算，冻结参数后重新训练正式模型；不得根据最终测试结果选择超参数或 checkpoint。

## 7.2 MuLoRA-FL

本地使用：

`B <- B - lr * MuonOperator(m)`

每个客户端的原始 momentum 在同一任务的通信轮之间保留，按真实 client ID 存储。任务切换时清零。这是项目的联邦状态约定。

## 7.3 FedMuon

对每个客户端、每个 B，保存原始 momentum `m_k` 和本地控制变量 `c_k`；服务器保存 `c`。

全参与、样本加权适配采用：

- 任务初始化：`m_k = c_k = c = 0`
- 本地每步：
  - `m_k <- beta*m_k + (1-beta)*g_k`
  - `h_k = m_k - c_k_old + c_old`
  - `B_k <- B_k - lr * MuonOperator(h_k)`
- 整轮本地训练中，`c_k_old` 和 `c_old` 固定；
- 整轮结束后：
  - `c_k_new = m_k_end`
  - `c_new = Σ_k p_k*c_k_new`
  - `B_new = Σ_k p_k*B_k_end`

不要把 corrected momentum 写回原始 m。
不要在每个 minibatch 更新 c_k。
不要把 correction 加在 NS 之后。
不要把它误写成 Adam 的时间偏差修正。

原论文采用 uniform-client objective。本项目样本加权及变长 local steps 属于 FCIL 适配，单独记录，不直接沿用原论文收敛结论。

保留一个 uniform weights、相同固定 local steps 的小型参考配置，验证论文 Algorithm 1。

主实验严格保持 E=5 epochs：

`K_k = 5 × len(train_loader_k)`

显式 `drop_last=False`，记录真实 K_k。不能为匹配固定 K 而静默截断、重复样本或改训练预算，也不能把 c_k 再除以 K_k。

同一任务内保留 m_k、c_k 和 c。新任务 A 改变且 B 清零时，这些状态一起重置。

## 7.4 官方代码审计

# 八、必须完成的正确性验证

只写能发现实质错误的测试，至少覆盖：

1. 不等客户端样本数下，二阶矩汇总等于拼接特征后的 X^T X；不存在重复样本数加权。

8. 统计管线不访问 validation/test/future 数据；评测使用全部已见类别且不接收真实 task ID。

- GPU 峰值显存；
- 参数、A、二阶矩、控制变量的实际通信字节；
- 总持久状态内存。

谱诊断区分单步 ΔB、任务累计 B 和聚合后的 B，不能用单步谱图声称累计更新一直平衡。

Checkpoint 至少包括：

- 已合并 backbone、当前 A/B、分类头；
- 历史二阶矩、待提交当前统计、计数；
- 真实 client ID 对应的 m_k、c_k；
- 服务器 c；
- task、round、scheduler；
- Python、NumPy、PyTorch、CUDA及数据采样 RNG；
- 配置、划分 manifest 和权重 hash；
- 历史统计是否已经提交的状态标志。

优先保证通信轮边界可准确恢复。保存采用原子写入，避免中断损坏。

# 十、执行顺序

## 阶段 A：环境与来源审计

- 检查硬件、可用 GPU、磁盘、数据和权重。
- 下载并固定公开来源。
- 阅读许可证并保留来源说明。
- 建立依赖环境并锁定实际验证通过的版本。
- 输出配置来源表：用户协议、MuLoRA原文、FedMuon原文/代码、项目补全。
- 在不影响正确性的情况下，单 GPU 串行模拟客户端即可，不要求先部署真实分布式集群。

## 阶段 B：数学测试与真实模型 smoke

先通过小矩阵/CPU reference 测试，再用真实 ViT 和 r32 做 smoke：

- 2 客户端；
- 正式类别划分中的前 2 个任务；
- 每任务 2 轮；
- 少量真实训练 batch；
- 两种方法都运行。

所有缩减仅存在于专用 smoke 配置，结果不能混入正式结果。

## 阶段 C：配对 pilot

- CIFAR-100 正式 10×10 划分的前 3 个任务；
- 10 客户端；
- α=0.05；
- 5 rounds × 5 local epochs；
- batch16、r32；
- seed0；
- 两种方法使用完全相同的数据 manifest。

检查状态、数值稳定性、新任务拟合、旧类保留和资源消耗。

## 阶段 D：正式实验

通过前面检查后，先完成两方法在 CIFAR-100、α=0.05、seed0 上的完整 10 任务训练。

再按可用资源运行完整矩阵：

`2 datasets × 3 alphas × 3 seeds × 2 methods = 36 runs`

用已有可用资源执行，不新开付费云实例。长任务保存检查点、日志与可恢复的运行队列。

不要在只完成 smoke 或 pilot 时宣布复现完成。若环境或会话限制导致部分实验尚未执行，明确记录已完成、运行中、未启动、失败和阻塞原因，并提供精确恢复命令。
